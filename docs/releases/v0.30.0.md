# v0.30.0 — Terminals' files readable again, an audit's fixes, a lighter page

A minor release: it fixes the findings of an audit of v0.29.0 and changes the protocol between
the page and terminumd (a page whose terminal is hidden asks for no screens) and how a remote
host's refused link is retried. `terminum upgrade` brings it.

## Fixed

- **New files made in a terminal were readable by you alone (0600, folders 0700)**: terminumd
  keeps its own files private with umask 077, and the tmux server it started, so every shell,
  coding agent and build in it, inherited that umask. A project deployed from a terminal of
  terminum could then fail where another user reads its files (a container's service, a web
  server). The tmux server terminumd starts now gets the umask terminumd was started with (022
  under launchd), and so do files and folders made in Files (new, a new file saved, a drop on
  the tree), on remote hosts too. **A tmux server already running keeps 077 until it restarts**
  (that ends its programs): until then `umask 022` in a shell, or a restart of tmux when
  nothing runs that you need.
- **Agents off given while agents on was still installing** (up to 10 minutes) was written over
  when the on finished. Now one on or off runs at a time for a host and the last asked wins: a
  later one stops the one running at once.
- **A reminder just made** got the bookmarks' orange wavy line beside its text; it is pink now,
  as a reminder brought into view.
- **Search in a pane whose output went on** found the right text but numbered its rows wrongly
  (48 of 50 answers in the audit's run); it now reads the history as the history view does.
- **Two pages showing one pane**: one got its screens at once, the other up to a second late;
  each now gets them at once.
- **Older history, unfolds and Files' folder no longer hold up keys** sent on the same
  connection: they run beside it, in the order sent.
- **A file opened raw** (a picture, a video, a download) is streamed instead of read whole, and a
  video's seek gets only the part it asks for; four held 64 MB files took 262 MB before.
- **The Files panel says when saving its tree, tabs or preferences fails** (once until a save
  works) and sends them again on the next change or reconnect; a save whose answer was lost is
  recognized, not repeated.
- **Sign-in and the page's start** give up on a server that does not answer within 5 s (then 10
  and 20 s) and say "No answer from terminum's server within N s", instead of waiting forever.
- **Remote hosts**: a link the host refused is retried after 10 minutes, then 20, 40, 80 and 160
  (it was retried only when the ssh ended); setting up agents uses the recipe read at its start
  and saves nothing over one changed meanwhile; agents off closes the link first; answers from
  the host are bounded; `terminum hosts …` waits as long as the server's steps can take and says
  when it gave up.
- **Bounded memory**: input waiting for tmux (4 MB or 10,000 items a page), commands waiting on
  a control client (16 MB), the listing cache's indexes, the installer's download (30 s to
  connect, 300 s in all).

## Changed

- **A session's menu** (a right click or a long press on its row) has Close Session first, set
  apart by a line; the keyboard's focus starts on Clone under it.
- **A computer keeps about 5000 history lines on the page** while it follows the output, as a
  phone keeps 2000; older lines load again on scrolling up. Every line stayed before, and each
  screen update laid them all out: with 20,000 lines and steady output (100 lines and 20
  screens a second) Chrome spent 39 ms on each update and a whole CPU core; now 6.5 ms and a
  fifth of a core. Safari: 15 ms then, 8 ms now.
- **Old lines are dropped less often**: only once the page is a fifth over its lines, down to
  them. Safari laid out the whole history after each drop: on a phone's 2000 lines an update
  took 14 ms, now 6 ms (measured in desktop WebKit).
- **A terminal hidden behind Files or a View** gets no screen updates and shows the latest at
  once when it is shown again.

## Verified

`make check` passes (733 Rust tests, Python, UI and Page unit tests, clippy, the Panel's browser
check 171/171, `web/test/e2e_live.mjs` 233/233 with vim, mc and Claude Code in both of its TUIs,
the Page's browser checks 1707/1707 in Chromium and WebKit at a wide and a phone size,
`scripts/security_check.sh`); `scripts/e2e_remote.py` 37/37, `scripts/e2e_remote_agents.py`
22/22, `scripts/e2e_remote_sshd_agents.py` 19/19 over a real sshd (Docker), `scripts/e2e_install.sh`.
The new checks: a new file and folder of Files and the tmux terminumd starts get the umask it
started with, a folder that was there keeps its mode (failed before: 0600, 0077); an agents off
during a long on stops it before it runs and the script on the host ends with its ssh; the
reminder's line pink just saved and brought into view (failed before: orange); the session menu's
order, its focus on Clone and a finger's lift that asks nothing; the history cap and its trim.
Measured: the page's work per screen update with 20,000 history lines (above). Reviewed before
the release with /simplify (the listing cache no longer waits on a running filter, no idle wake-up
of every page each second, a frame's few rows parsed in place, raw files in 256 KiB reads, the
CLI's waits summed from the server's named limits) and by a pragmatic review of the umask, the
agents' turns, the reminder's line and the menu.

Measured, not changed: a pane printing without pause (several MB a second) on a remote host
delays the echo and screens of the other panes of its tmux session over the same ssh (0.5–1.8 s
on a host 110 ms away; a build log or an agent's screen, under 130 kB/s, delays nothing).
Turning off an unshown pane's output with tmux's `refresh-client -A %N:off` (or `:pause`) would
avoid it, but it crashed the whole tmux server in tests (tmux 3.4 and 3.6a), so terminum does
not use it.

Noticed, not fixed: the helper's copy to a host (Files, agents on) leaves its side on the host
running when it is stopped; only the agents' scripts end with their ssh. From the reviews, left
for later: terminumd's own files could take explicit modes instead of the process-wide umask 077
it gives back to tmux and Files; a host's agents turn could keep the last asked state.

Not verified: a physical iPhone and the user's own signed-in Safari (the phone's history cap
measured in desktop WebKit only); a tmux server started before this release keeps umask 077
until it restarts (not restarted here).
