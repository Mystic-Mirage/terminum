# v0.27.2 — diffs of wide tables, host agents after a dropped link, a green CI

A patch release: fixes only. `terminum upgrade` brings it.

## Fixed

- **A numbered diff of a wide Markdown table** (Claude Code's view of an edit) stayed text when a
  row was wider than the pane: Claude Code continues such a row on the next lines without a
  number. The parts are joined again, a word cut by the width whole, and the diff is one table.
- **Agents on a host said "terminum's hooks are not running"** after the host's link dropped or
  terminumd restarted, until their next prompt. The next event of a running session (any tool
  call, terminum's own too) brings its state back; a session that ended stays without one.

## For contributors

- CI on the Linux runner passes again. A worktree check probed copy-on-write copies with an
  empty folder, which copies on any disk, and then expected cloned `node_modules` (every run since
  2026-11-01); an ssh-link check ran a script it had just written, which Linux can refuse while
  another test's fork holds it open (ETXTBSY). On Linux the live check skips Finder drops (their own
  paths are macOS's), and WebKit's own report of a failed load the code caught ("Fetch API cannot
  load … due to access control checks", the old WebKit "no page errors" flake) is printed, not
  counted. Each run reports rustc's peak memory (1.3 GB) and the runner's cap hits (none at 2G),
  and a stuck build stops after 20 minutes instead of 60.
- The browser checks no longer make WebKit play the Mac's alert sound: a ⌘X the page leaves to
  the browser over text that is not editable beeped on every run; the check sends that key to the
  page's handler alone.

## Verified

`make check` passes (699 Rust tests, Python, UI and Page unit tests, clippy, the Panel's browser
check 167/167, `web/test/e2e_live.mjs` 231/231 with vim, mc and Claude Code in both of its TUIs,
the Page's browser checks 1623/1623 in Chromium and WebKit at a wide and a phone size,
`scripts/security_check.sh`); `scripts/e2e_remote.py` 37/37 for the host links; on the Linux
runner the unit tests pass again (the first run since 2026-11-01). A WebKit run of the browser
checks while macOS's sound log was watched: the ⌘X check was the only alert sound, and none since.

Not verified: a physical iPhone and the user's own signed-in Safari; the host agents' fix on a
real host whose link drops while an agent works (checked by `cargo test tmux::hookstate`).
