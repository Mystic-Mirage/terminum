# v0.27.1 — a mark for full-screen programs; a host's agents keep terminum's tools

A patch release: fixes and small changes to the existing UI. `terminum upgrade` brings it.

## New in the UI

- **A full-screen mark in the header.** While the shown session runs on its alternate screen
  (Claude Code's fullscreen TUI, vim, mc), an icon after the agent's says so ("Full screen mode"
  on hover). There the page shows the program's own grid: no history and no widgets, so a
  table Claude Code draws stays text. Codex's alternate screen keeps both and shows no mark.
- **Menus with icons.** A session's menus show an icon before each item; Close Session, Close
  Project… and Close Group… carry a red ×; Split Below, Right and Left stand in one row, each
  a drawing of its split.
- **Counts in a ring.** The bookmarks' and reminders' counts on their buttons sit in a ring (an
  ellipse for two digits), clear of the icon.

## Fixed

- **Agents on a host lost terminum's tools.** `terminum mcp` asked about its pane once, as the
  agent started, and kept a "no" when nothing answered (a link reconnecting, terminumd
  restarting): that session made no bookmarks, reminders or plan until it ended. It now offers
  the tools whenever nothing answers, and finds the links at each call.
- **A `git diff` of a Markdown table** showed its head as a table and its rows as text; it is
  one table, its rows marked as added, removed or kept.
- **New File… did nothing** in Files when the selection kept with the pane was in another folder
  or under a closed one: the name's field had nowhere to show. It opens in the root then.
- **An unread row's hatching** is drawn in whole pixels, no longer blurred over two in some rows.

## A correction to v0.27.0

Its notes said open pages stay signed in across that upgrade. A page or a Files panel loaded
from 0.26 still sends the old sign-in, which 0.27 refuses from a browser: such a page asks for
the password once. Pages loaded from 0.27 on are not affected.

## Verified

Panel's browser check 167/167, `web/test/e2e_live.mjs` 231/231 with vim, mc and Claude Code in
both of its TUIs in a private tmux, the Page's browser checks 1623/1623 in Chromium and WebKit at

links. Two timing checks were made to wait for what they test (Ask's switch-away, the live New
File check, which found the New File fix above).

Noticed, not fixed: under heavy load (a backup running) WebKit's live run sometimes failed other
