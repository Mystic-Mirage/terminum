# v0.30.2 — A terminal in sight keeps drawing; ⌘Enter in the dialogs

A patch release: two fixes and a keyboard shortcut for dialogs that already exist. `terminum upgrade` brings it.
A patch rather than a minor: the page's "pause" message gains an optional field. The page and
terminumd ship in the same binary, and a page from before this release still works with this one.

## Fixed

- **The terminal stopped while another app had the focus.** On a computer, a browser window
  that lost the focus stopped receiving the terminal's output, even with the window still in
  sight. A click in it scrolled to the end and showed everything at once. Now only a hidden page
  (another tab, a minimized window, a locked phone) pauses. A window in sight without the focus
  keeps drawing the output and the session list. It still leaves the pane's size to the page in
  use and does not mark a finished agent's turn as read.
- **CI of v0.30.0 and v0.30.1** (the binaries were not affected):
  - a lost ssh link could be reported as "ssh: no answer from the host" before ssh's own words
    on stderr were read; the reason now waits up to 1 s for them;
  - a cast in the umask code was rejected by clippy on Linux.

## New

- **⌘Enter or Ctrl+Enter** in the Bookmark (and Reminder) dialog is Save, and in Ask it is Add to
  Chat; a plain Enter is still a new line, and nothing happens while the button is off.

## Verified

`make check` passes: Rust tests, clippy, the Panel's browser check, `web/test/e2e_live.mjs`, and
the Page's browser checks in Chromium and WebKit, plus `scripts/security_check.sh`. A new live
check runs a real terminumd and a private tmux in Chromium and WebKit:
- a page in sight without the focus draws an `echo`'s output (76 ms);
- a hidden page draws none in 1.5 s;
- shown again, still without the focus, it gets that output.

The browser's focus and visibility are simulated: a test cannot move the window's focus to
another app. The dialogs' keys are checked in both engines (64/64). The CI run of 4c5fa1d passed
every step. Reviewed with /simplify, and its fixes are in:
- the page's look is one value (on, away, hidden) instead of two flags;
- a pane opened while the page is hidden starts paused;
- the stderr wait runs only when tmux sent no `%exit`;
- the umask code needs no cast exception.

Not verified:
- the owner's own Safari and Chrome with another app in front;
- whether a browser pauses a window that another window covers completely (if it does not, that
  window also keeps streaming).
