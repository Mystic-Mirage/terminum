# v0.30.1 — Files on a macOS host, zsh-safe attach commands

A patch release: two fixes for zsh, macOS's shell. `terminum upgrade` brings it.

## Fixed

- **Files never enabled on a macOS host** (issue #8): the helper's install ran in the host's
  login shell, and zsh, macOS's default, stopped it at a cleanup of old helpers when there was
  none ("no matches found: …/terminusd-agent-*"), so a helper that had been copied was reported
  as failed. Every command terminum runs on a host for its helper (the platform's probe, the
  copy, its start, its removal) now runs under `/bin/sh` whatever the login shell; fish and csh
  hosts no longer fail Files either.
- **A group's copied attach command failed in zsh**: `tmux -L terminum attach -t =main` said
  "main not found", as zsh reads a word starting with `=` as a program's path (a session named
  like a program attached to its path). The target is quoted now: `attach -t '=main'`, and a
  host's `ssh -t … "tmux attach -t '=terminum'"`.

check, `web/test/e2e_live.mjs`, the Page's browser checks in Chromium and WebKit,

"no matches found", as the issue reported; zsh reads the quoted attach target as written.

the /bin/sh wrapper is one function every ssh to a host goes through.
